# Безопасность

HealtHosted — self-hosted приложение для одного владельца: медицинские данные лежат
в SQLite и файлах на вашем сервере, наружу ничего не отправляется (кроме координат города
в погодные API, и только при включённом разделе «Сезон»). Телеметрии нет.

## Как сообщить об уязвимости

Не открывайте публичный issue. Используйте GitHub Security Advisories:
вкладка **Security → Report a vulnerability** в репозитории. Ответ — в течение 7 дней.
Укажите версию (`/api/health`), способ установки (Docker/локально), шаги воспроизведения
и влияние. Пожалуйста, не прикладывайте реальные медицинские данные.

## Модель угроз

Проект рассчитан на личный сервер или домашнюю сеть:

- единственный пользователь-владелец, регистрация закрывается после первого аккаунта;
- пароли — scrypt, сессии — случайный 256-битный токен, хранится хешем, cookie HttpOnly;
- файлы отдаются только владельцу через `/api/files/<id>` после проверки сессии;
- все изменяющие запросы проверяют `Origin` (CSRF), вход и регистрация — rate-limit;
- никакой внешней аутентификации, OAuth и облачных бэкендов.

Вне модели: multi-tenant изоляция, роли и права, аудит для нескольких пользователей.

## Обязательные меры при публикации в интернет

Приложение само по себе **не заменяет TLS и не рассчитано на прямой выход в интернет**:

1. Поставьте перед контейнером reverse-proxy с HTTPS (Caddy, nginx+Let's Encrypt, Traefik).
2. Оставьте `BIND_ADDR=127.0.0.1` и проксируйте на него; не пробрасывайте порт 3000
   напрямую с роутера.
3. Ограничьте доступ (VPN, Tailscale, basic-auth на прокси, allow-list IP), если сервер
   не должен быть публичным.
4. Делайте бэкапы тома (`./scripts/backup.sh`) и храните копию вне сервера.
5. Проверяйте обновления зависимостей (`npm audit`) перед крупными релизами.

## Что считается уязвимостью

- обход аутентификации, доступ к чужим файлам/записям, CSRF, SQLi, XSS, path traversal;
- утечка данных в логи, ошибки, экспорт или внешние запросы;
- повышение прав, обход rate-limit, предсказуемые токены.

Не считаются: отсутствие TLS «из коробки», отсутствие 2FA, доступ к сервису при
`BIND_ADDR=0.0.0.0` в доверенной сети, отсутствие аудита для одного пользователя.
