# HealtHosted

Self-hosted личный медицинский архив: медкнижка, история болезней, визиты врача,
анализы с референсами, измерения, отчёт для врача и экспорт. Один Docker-контейнер,
SQLite, без внешних сервисов и телеметрии.

## Возможности

- **Аккаунт** — единственный владелец; регистрация закрывается после создания первого
  пользователя. Пароли — scrypt, сессии на случайных токенах, rate-limit, аудит.
- **Измерения** — вес, рост, давление, пульс, температура, сатурация, глюкоза, ИМТ, график веса.
- **Болезни, визиты, медкнижка** — МКБ-10 и статусы, врач и заключение, прививки и
  медосмотры со сроками действия, вложения (PDF/JPG/PNG до 25 МБ).
- **Анализы** — панели по типам, справочник 97 тестов / 150 правил / 24 пересчёта единиц,
  автофлаги отклонений, panic values, PDF бланка.
- **Отчёт и экспорт** — сводка для врача с печатью в PDF, выгрузка всего архива в zip.
- **Сезон и аллергии** — оценка риска ОРВИ и аллергии по среде (погода, воздух, пыльца);
  включается вручную, по умолчанию выключено.

## Быстрый старт

Docker Engine 24+ с Compose v2, 1 ГБ RAM, 2 ГБ диска, свободный порт 3000.

```bash
git clone https://github.com/tunyanakop/healthosted.git
cd healthosted
cp .env.example .env            # опционально: дефолты рабочие
docker compose up -d --build
sh scripts/smoke.sh             # 5 проверок: health, login, защита без сессии
```

Открыть `http://127.0.0.1:3000` → «Создать первый». После этого регистрация закрыта
навсегда. Первая сборка — 2–4 минуты, дальше старт занимает секунды.

Проверка: `docker compose ps` (STATUS = `healthy`), `curl -s http://127.0.0.1:3000/api/health`.

Данные — в томе `healthosted_data` (`/data`: SQLite + файлы). Удаление контейнера их не
трогает, `docker compose down -v` — удаляет.

**Доступ из локальной сети:** поставить в `.env` `BIND_ADDR="0.0.0.0"` и перезапустить.
Трафик по HTTP не шифруется — для домашней сети приемлемо, наружу только через TLS-прокси
(Caddy, nginx, Traefik), без проброса порта на роутере.

## Переменные окружения

Все опциональны, секретов и ключей проект не требует: `DATABASE_URL` (по умолчанию
`file:/data/app.db`), `DATA_DIR` (`/data`), `BIND_ADDR` (`127.0.0.1`), `PORT` (`3000`),
`ENV_WEATHER_PROVIDER` (`auto` / `open-meteo` / `met.no` / `wttr.in`),
`ENV_AIR_PROVIDER` (`open-meteo` / `none`).

## Обновление и бэкап

```bash
sh scripts/backup.sh          # tar.gz тома в ./backups
git pull
docker compose up -d --build  # миграции применяются автоматически при старте
```

Восстановление — `sh scripts/restore.sh backups/healthosted-*.tar.gz`. Том при обновлении
не трогается. Копию храните **вне** сервера: том и бэкап на одном диске не спасают.

## Локальная разработка

Node.js 22+ (в `.nvmrc` — 24), npm 10+:

```bash
npm ci --include=dev
cp .env.example .env
npx prisma migrate deploy
npm run dev
```

Перед коммитом: `npm run build`, `npx tsc --noEmit`, `npm test` (133 теста).
Структура: `src/app` — страницы и API, `src/lib` — доменная логика, `prisma` — схема
и миграции, `scripts` — backup/restore/smoke, `tests` — vitest.

## Ограничения

- SQLite — один писатель: для личного архива достаточно, для семьи 3+ человек — PostgreSQL.
- Нет интеграций с лабораториями: только ручной ввод и загрузка файлов. HEIC с iPhone
  не поддерживается без конвертера.
- Сборка проверена на x86_64; на arm64 не прогонялась. Медицинских рекомендаций
  приложение не даёт и врача не заменяет.

## Если что-то пошло не так

- **`connection refused` с другого компьютера** — `BIND_ADDR` не `0.0.0.0` или порт
  закрыт файрволом. **Контейнер unhealthy** — `docker compose logs app`: обычно занят
  порт 3000 или нет прав на том `/data`.
- **«Источник данных о среде недоступен»** — сервер не достучался до внешнего API.
  Поставьте `ENV_WEATHER_PROVIDER=met.no`; кнопка «Проверить источники данных» в разделе
  «Сезон» покажет ответ каждого провайдера.
- **Забыт пароль** — восстановления по email нет: пересоздать том или удалить пользователя
  через `prisma studio`. Данные при этом теряются — держите бэкапы.
