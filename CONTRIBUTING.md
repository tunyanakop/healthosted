# Участие в разработке

Спасибо, что заглянул. Проект маленький и прикладной: личный медицинский архив,
который ставится одним контейнером. Приветствуются баг-репорты, переводы, аккуратные
правки UI и новые правила расшифровки анализов.

## Что нужно

- Node.js 22+ (в CI и Docker — 24)
- npm 10+
- Docker — только если проверяешь установку в контейнере

## Локальный запуск

```bash
npm ci --include=dev
cp .env.example .env
npx prisma migrate deploy
npm run dev
```

Открыть `http://127.0.0.1:3000` и создать первого пользователя: он становится владельцем,
дальнейшая регистрация закрывается.

## Перед PR

```bash
npx tsc --noEmit   # типы
npm test           # vitest, 133 теста
npm run build      # production-сборка
```

Все три должны быть зелёными: их же гоняет CI.

## Правила

- **Не коммить личные данные.** `.env`, `prisma/*.db`, `data/`, `backups/` уже в
  `.gitignore`; реальные анализы в тестах и скриншотах недопустимы.
- **Тесты — на чистых функциях.** Логика живёт в `src/lib/*.ts`; файлы с `server-only`
  (Prisma, сессии, сеть) тестами не покрываются — выносите расчёты в отдельный модуль,
  как это сделано в `reference-core.ts` и `lab-patterns.ts`.
- **Миграции только через Prisma.** `npx prisma migrate dev --name название` — не
  редактируйте применённые файлы в `prisma/migrations/`.
- **Деньги, здоровье и приватность.** Никакой телеметрии, внешних SDK и «облачных»
  вызовов с персональными данными. Сетевые запросы — только погода/воздух по координатам
  и только при явно включённом разделе «Сезон».
- **Медицинские утверждения.** Приложение не ставит диагнозов. Тексты в интерфейсе
  должны это подчёркивать; формулировки «рекомендуется лечить» не принимаются.
- **Стиль.** TypeScript strict, 2 пробела, Tailwind-классы в существующей палитре
  (`ink`, `accent`), интерфейс на русском.

## Что писать в PR

- что меняется и зачем, как проверить (шаги, ожидаемый результат);
- для UI — скриншот до/после без личных данных;
- отдельной строкой — что проверить не удалось (например, `docker build` без демона).

## Релизы

Версия в `package.json` и строка статуса в `README.md`. Порядок: тесты → `build` →
`docker compose up -d --build` → `sh scripts/smoke.sh` → коммит `Версия X.Y.Z`.
